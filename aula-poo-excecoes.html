Falhas e exceções

Quando o programa encontra um imprevisto

Seu código está correto, mas o mundo real nem sempre colabora: o usuário digita letra onde era número, o arquivo foi apagado, a internet caiu, o servidor não respondeu. Chamamos isso de falha — e o Python avisa criando uma exceção.

Exceção é um objeto que o Python cria para dizer: "aconteceu algo fora do previsto aqui".
Tratar a exceção é decidir o que fazer nesse caso, em vez de deixar o programa quebrar na cara do usuário.
Falhas e exceções

Dois problemas bem diferentes

Erro de sintaxe

O código está escrito errado

if idade > 18 print("maior") SyntaxError: expected ':'

O Python nem começa a rodar o programa. Faltou dois-pontos, parêntese, aspas... Não dá para tratar: tem que consertar o código.

Exceção

O código está certo, mas algo deu errado

idade = int(input("Idade: ")) # usuário digitou "abc" ValueError: invalid literal for int()

O programa começou a rodar e travou no meio, por causa de um dado ou de uma situação inesperada. Isso, sim, dá para tratar.

Regra prática: se o erro aparece antes de qualquer print ser executado, provavelmente é sintaxe. Se o programa rodou um pouco e parou, é exceção.
Falhas e exceções

Lendo a mensagem de erro

Aquele bloco vermelho assustador se chama traceback e é o seu melhor amigo na hora de depurar. Leia sempre de baixo para cima.

Traceback (most recent call last): File "media.py", line 7, in <module> media = calcular(notas) File "media.py", line 3, in calcular return sum(lista) / len(lista) ZeroDivisionError: division by zero
  1. Última linha: o tipo da exceção e a mensagem. É o que você procura no Google.
  2. Linha acima dela: exatamente o comando que quebrou.
  3. Arquivo e número da linha: onde procurar no seu código.
  4. De cima para baixo: o caminho que o programa percorreu até chegar lá.
Aqui a lista notas chegou vazia, então len(lista) deu 0.
Captura de exceções

try e except: a rede de proteção

try: idade = int(input("Sua idade: ")) print(f"Ano que vem: {idade + 1}") except ValueError: print("Digite apenas números!") print("O programa continua rodando.")
Com "abc" o programa não quebra: mostra a mensagem amigável e segue em frente.

Lendo o bloco em português

  • try — tente executar estas linhas.
  • except — se acontecer uma exceção desse tipo, faça isto em vez de quebrar.
Dentro do try coloque só o que pode falhar. Um try gigante esconde de você onde está o problema de verdade.
O except não conserta o erro: ele decide o que fazer quando o erro acontece. Muitas vezes o certo é pedir o dado de novo.
Captura de exceções

Como o Python percorre o bloco

Só um except roda. Encontrado o primeiro que combina, os outros são ignorados.
O resto do try é abandonado. As linhas depois do ponto do erro não são executadas.
Depois de tratado, a vida segue. O programa continua da linha seguinte ao bloco.
Captura de exceções

Cada problema, uma resposta

try: n = int(input("Um número: ")) print(100 / n) print(nomes[n]) except ValueError: print("Isso não é um número inteiro.") except ZeroDivisionError: print("Não dá para dividir por zero.") except (IndexError, KeyError): print("Essa posição não existe.")

O que está acontecendo

  • O Python testa os except de cima para baixo e executa apenas o primeiro que combina.
  • Vários tipos com a mesma resposta? Agrupe em uma tupla: except (IndexError, KeyError):
  • Assim o usuário recebe uma mensagem que explica o problema dele, não um traceback.
Evite o except: pelado. Ele captura literalmente tudo — inclusive o Ctrl+C do usuário querendo fechar o programa — e esconde bugs seus.
Captura de exceções

O bloco completo: else e finally

notas = [7.5, 8.0, 6.2] try: pos = int(input("Posição da nota: ")) nota = notas[pos] except ValueError: print("Digite um número inteiro.") except IndexError: print("Essa posição não existe.") else: print(f"Nota encontrada: {nota}") finally: print("Consulta encerrada.")
BlocoQuando roda
trysempre — é a tentativa
exceptsó se ocorrer aquele tipo de exceção
elsesó se não ocorrer nenhuma exceção
finallysempre, com erro ou sem erro
O else só roda quando nada deu errado. Isso deixa o try enxuto: nele fica só o que pode falhar; o resultado fica no else.
O finally é o lugar de encerrar o que você começou — liberar um recurso, registrar no log, avisar que a operação terminou. Ele vai ser bem útil quando chegarmos em arquivos.
Captura de exceções

Guardando a exceção em uma variável

try: numero = int("abc") except ValueError as erro: print("Deu problema:", erro) print(type(erro)) print(erro.args) # Deu problema: invalid literal for int() # with base 10: 'abc' # <class 'ValueError'> # ("invalid literal for int()...",)

Exceção é objeto: tem tipo, atributos e métodos, como qualquer outro objeto que vocês já criaram.

  • as erro guarda o objeto na variável erro.
  • print(erro) mostra a mensagem que o Python gerou.
  • erro.args é a tupla com os argumentos da exceção.
A mensagem original é escrita para o programador, em inglês. Use-a no log; para o usuário final, escreva uma mensagem em português e sem jargão.

Atividade 1 — Calculadora que não quebra

Tempo: 15 minutos

Crie o arquivo calculadora.py que peça dois números e mostre a divisão do primeiro pelo segundo. Depois:

  1. Trate o caso de o usuário digitar texto em vez de número.
  2. Trate o caso de o segundo número ser zero.
  3. Use else para mostrar o resultado só quando der tudo certo.
  4. Use finally para escrever "Operação finalizada".
  5. Desafio: repita a pergunta até o usuário digitar valores válidos (dica: while True + break).

Ponto de partida

while True: try: a = float(input("Número 1: ")) b = float(input("Número 2: ")) r = a / b except ...: ... else: print(r) break
Teste com 10 e 0, depois com dez. Cada teste precisa cair em um except diferente.
Lançamento de exceções

raise: lançando uma exceção de propósito

def definir_idade(idade): if not isinstance(idade, int): raise TypeError("Idade deve ser inteiro") if idade < 0: raise ValueError("Idade não pode ser negativa") return idade # quem chama decide o que fazer try: definir_idade(-5) except ValueError as e: print("Dado inválido:", e)

Por que não usar só um print?

  • Um print avisa, mas o programa continua com o dado errado e o estrago aparece lá na frente.
  • O raise interrompe na hora e obriga quem chamou a função a lidar com o problema.
  • Sua função fica reutilizável: ela avisa o que houve, e cada programa decide se mostra na tela, grava em log ou pede de novo.
Divisão de papéis: quem detecta o problema usa raise; quem sabe o que fazer com ele usa except.
Lançamento de exceções

A exceção sobe até alguém tratar

Relançar depois de registrar

try: media = calcular_media(notas) except ZeroDivisionError as e: print("Turma sem notas:", e) raise # manda a exceção adiante
raise sozinho, dentro de um except, relança a mesma exceção. Útil quando você quer registrar o problema mas não é você quem deve resolvê-lo.
Trate a exceção onde existe informação suficiente para decidir. Uma função de cálculo raramente sabe se deve mostrar uma janela de erro ou tentar de novo.
Hierarquia da biblioteca padrão

Exceções são classes — e formam uma família

Toda exceção do Python é uma classe, e essas classes herdam umas das outras. Quem está mais acima na árvore é mais genérico; quem está embaixo é mais específico.

Herança na prática: except ArithmeticError também captura ZeroDivisionError, porque toda ZeroDivisionError é uma ArithmeticError.
Nunca use except BaseException. Ele impede até o Ctrl+C de encerrar o programa. Sua rede de segurança máxima é Exception.

Hierarquia da biblioteca padrão

A ordem dos except importa

Errado — do geral para o específico

try: print(10 / 0) except Exception: print("Algum erro aconteceu") except ZeroDivisionError: print("Divisão por zero") # nunca será executado
Como ZeroDivisionError é filha de Exception, o primeiro except já captura tudo. O segundo vira código morto.

Certo — do específico para o geral

try: print(10 / 0) except ZeroDivisionError: print("Divisão por zero") except Exception as e: print("Erro inesperado:", e)
Primeiro os casos que você sabe explicar; por último, um Exception genérico como rede de segurança — e sempre mostrando o erro, nunca engolindo em silêncio.

Atividade 2 — Cadastro com validação

Tempo: 15 minutos

Escreva a função cadastrar_aluno(nome, idade, nota) que lança exceções da biblioteca padrão quando os dados não fazem sentido:

  1. ValueError se o nome for vazio.
  2. ValueError se a idade não estiver entre 10 e 100.
  3. ValueError se a nota não estiver entre 0 e 10.
  4. TypeError se a nota não for um número.
  5. No programa principal, chame a função dentro de um try e mostre uma mensagem clara para cada problema.

Casos de teste obrigatórios

cadastrar_aluno("", 16, 8) cadastrar_aluno("Ana", 5, 8) cadastrar_aluno("Ana", 16, 15) cadastrar_aluno("Ana", 16, "oito") cadastrar_aluno("Ana", 16, 8) # válido
Escreva na mensagem da exceção o que foi recebido: f"Idade inválida: {idade}". Isso economiza horas de depuração depois.
Criação de classes de exceção

Criando a sua própria exceção

class SaldoInsuficienteError(Exception): """Saque maior que o saldo da conta.""" def sacar(saldo, valor): if valor > saldo: raise SaldoInsuficienteError( "Saldo insuficiente para o saque") return saldo - valor try: sacar(100, 250) except SaldoInsuficienteError as e: print("Operação negada:", e)

É só uma classe que herda de Exception

  • Herde sempre de Exception (nunca de BaseException).
  • O corpo pode ser só uma docstring ou pass — a classe já funciona.
  • Por convenção, o nome termina em Error e usa CamelCase.
Por que criar a minha? SaldoInsuficienteError diz exatamente o que aconteceu no seu sistema. Um ValueError genérico se confunde com qualquer outro erro de valor do programa.
Criação de classes de exceção

Exceções que carregam informação

class SaldoInsuficienteError(Exception): def __init__(self, saldo, valor): self.saldo = saldo self.valor = valor self.falta = valor - saldo super().__init__( f"Faltam R$ {self.falta:.2f}")
except SaldoInsuficienteError as e: print(e) # Faltam R$ 150.00 print(e.saldo, e.falta) # 100 150

O que ganhamos com isso

  1. O __init__ recebe os dados do problema e os guarda como atributos.
  2. O super().__init__(...) monta a mensagem da exceção — é o que aparece no print(e).
  3. Quem captura pode usar e.falta para sugerir um depósito, gerar um relatório ou tomar uma decisão.
Tudo isso é herança e polimorfismo, os mesmos conceitos das aulas anteriores — aplicados a uma classe que já existe no Python.
Criação de classes de exceção

Uma família de exceções para o seu projeto

class BancoError(Exception): """Base de todos os erros do banco.""" class SaldoInsuficienteError(BancoError): pass class ContaInexistenteError(BancoError): pass
Agora except BancoError captura qualquer erro do seu sistema de uma vez — e você ainda pode tratar um caso específico antes, se quiser.
É exatamente a mesma ideia da hierarquia do Python: do específico para o geral.
Boas práticas

O que fazer e o que evitar

Faça

  • Capture o tipo mais específico que você consegue tratar.
  • Deixe no try só as linhas que podem falhar.
  • Escreva mensagens que ajudem: o que houve e o que o usuário deve fazer.
  • Use finally para encerrar o que você começou.
  • Crie exceções próprias quando o erro for uma regra do seu domínio.

Evite

try: processar() except: # captura até Ctrl+C pass # e apaga o rastro do bug
  • Engolir a exceção com pass: o erro vira um mistério.
  • Usar exceção como if: se dá para testar antes, teste antes.
  • Mostrar o traceback cru para o usuário final.
  • Um try gigante em volta do programa inteiro.
O pior erro é o silencioso. Se você não sabe o que fazer com uma exceção, é melhor deixá-la subir do que fingir que nada aconteceu.
Juntando tudo

Exemplo completo: caixa eletrônico

class BancoError(Exception): """Erro base do sistema bancário.""" class SaldoInsuficienteError(BancoError): def __init__(self, saldo, valor): self.falta = valor - saldo super().__init__(f"Faltam R$ {self.falta:.2f}") class ValorInvalidoError(BancoError): pass def sacar(saldo, valor): if valor <= 0: raise ValorInvalidoError("O valor deve ser positivo") if valor > saldo: raise SaldoInsuficienteError(saldo, valor) return saldo - valor
saldo = 100.00 try: valor = float(input("Valor do saque: ")) saldo = sacar(saldo, valor) except ValueError: print("Digite um número válido.") except SaldoInsuficienteError as e: print("Saque negado.", e) print(f"Deposite R$ {e.falta:.2f} antes.") except BancoError as e: print("Operação inválida:", e) else: print(f"Saque efetuado. Saldo: R$ {saldo:.2f}") finally: print("Retire seu cartão.")
Repare na ordem: SaldoInsuficienteError vem antes de BancoError, que é a sua mãe.

Fechando

O que aprendemos hoje

  • Exceção é o aviso do Python de que algo saiu do previsto durante a execução.
  • try / except capturam o problema; else roda quando dá tudo certo e finally roda sempre.
  • raise lança uma exceção quando o seu código detecta que uma regra foi quebrada.
  • As exceções formam uma hierarquia de classes: capture do específico para o geral.
  • Você pode criar suas próprias exceções herdando de Exception.
Próximos passos: pegue um programa que você já escreveu e proteja as entradas dele. Todo programa que fala com o usuário precisa disso.
except Exception as e:

Programa robusto não é o que nunca encontra problemas: é o que sabe exatamente o que fazer quando eles aparecem.
