O PROBLEMA

A memória do programa esquece tudo

Tudo o que você cria em Python — objetos, listas, dicionários — vive na memória RAM. Quando o programa termina, essa memória é devolvida ao sistema e o conteúdo se perde.

Já aconteceu com você

Você cadastra 20 livros no seu sistema, testa tudo, fecha o programa… e na próxima execução a lista está vazia de novo.

A pergunta da aula

Como fazer os dados sobreviverem ao fim do programa?

CONCEITO

Persistência é fazer o dado durar

Persistência é a capacidade de um dado continuar existindo depois que o programa que o criou terminou. Na prática: gravar em um lugar que não depende de energia elétrica — disco, pen drive, nuvem.

Volátil

Memória RAM. Rápida, mas apaga tudo ao desligar. É onde seus objetos vivem enquanto o programa roda.

Persistente

Disco (HD, SSD), pen drive, nuvem. Mais lento, mas o conteúdo continua lá amanhã.

O caminho entre os dois

É disso que trata a aula de hoje: como levar o dado da RAM para o disco e trazê-lo de volta.

Persistir não é a mesma coisa que salvar em banco de dados. Banco de dados é uma das formas de persistir. Arquivo é a mais simples — e é por ela que se começa.

Um arquivo bem usado resolve muito mais do que parece. Sistemas inteiros de configuração — inclusive os do próprio Python — são só arquivos de texto.

CONCEITO

O que é um arquivo, de verdade

Um arquivo é uma sequência de bytes gravada no disco, com um nome e um endereço (a pasta onde mora). Só isso.

Não existe "linha"

O disco não sabe o que é linha. A quebra de linha é só mais um caractere: \n.

Ordem importa

Os bytes são lidos em sequência, do começo ao fim, como uma fita.

A extensão não muda nada

.txt, .csv, .py são convenções para humanos e programas. O conteúdo é o mesmo tipo de coisa.

DOIS TIPOS DE ARQUIVO

Texto e binário

A diferença está em como os bytes devem ser interpretados — e é você quem avisa isso ao Python na hora de abrir.

Arquivo de texto

Os bytes representam caracteres. Você consegue abrir no Bloco de Notas e entender. Exemplos: .txt, .csv, .json, .py, .html.

Dom Casmurro|1899 Vidas Secas|1938

Arquivo binário

Os bytes representam qualquer outra coisa: pixels, som, uma estrutura interna. Abrir no Bloco de Notas mostra símbolos sem sentido. Exemplos: .png, .mp3, .zip, .pdf.

Nesta aula trabalharemos com texto. Será apresentado brevemente o modo binário no final do assunto.

CONCEITO-CHAVE

Fluxo: o canal entre o programa e o arquivo

Seu programa nunca toca o disco diretamente. Ele abre um fluxo (em inglês, stream) e envia ou recebe dados por esse canal, um pedaço de cada vez.

Pense em uma mangueira ligando a caixa d'água à torneira. A água passa aos poucos, sempre na mesma direção, e alguém precisa abrir e depois fechar o registro.

DUAS DIREÇÕES

Fluxo de entrada e fluxo de saída

O nome sempre é dado do ponto de vista do programa: entra nele ou sai dele.

Entrada — leitura

Os dados vêm do arquivo para o programa. É o que acontece quando o sistema é iniciado e precisa carregar o que foi salvo antes.

Saída — escrita

Os dados vão do programa para o arquivo. É o que acontece quando o usuário cadastra algo novo e você salva.

Você já usa fluxos sem perceber: input() lê do fluxo do teclado e print() escreve no fluxo da tela.

O RITUAL DE SEMPRE

Abrir, usar, fechar

Todo trabalho com arquivo segue estes três passos, nesta ordem. Pular o último causa problemas difíceis de descobrir.

Sem close(), parte do que você escreveu pode ficar presa em um buffer na memória e nunca chegar ao disco. Daqui a pouco vamos ver o with, que fecha sozinho.

A FUNÇÃO CENTRAL

Anatomia do open()

Uma única função abre o canal e devolve um objeto que representa o arquivo aberto.

O que open() devolve

Não é o conteúdo do arquivo. É um objeto com métodos como read(), write() e close() — o seu controle remoto do fluxo.

Se o modo não for informado

Python assume "r" (leitura de texto). Mesmo assim, escreva o modo: quem lê o código depois agradece.

SEGUNDO ARGUMENTO

Os modos de abertura

O modo diz duas coisas: o que você pode fazer com o arquivo e o que acontece com o conteúdo que já estava lá.

ModoSignificaSe o arquivo existeSe não existeUsar quando
"r"read — só leituraLê do começoErro FileNotFoundErrorCarregar dados salvos
"w"write — só escritaApaga tudo e começa vazioCria o arquivoRegravar a lista inteira
"a"append — acrescentarEscreve no final, preserva o restoCria o arquivoRegistrar um novo item, um log
"x"exclusive — criarErro FileExistsErrorCria o arquivoGarantir que não vai sobrescrever
"r+"ler e escreverAbre sem apagarErroCasos específicos, raro no início
Acrescentar "b" ao modo ("rb", "wb") muda para binário. Sem o b, o modo é sempre de texto.

ARMADILHA CLÁSSICA

O modo "w" apaga antes de escrever

Ele não avisa, não pergunta e não tem desfazer. O conteúdo antigo simplesmente deixa de existir no instante em que o arquivo é aberto.

o que você quis fazer
# só queria adicionar mais um livro…
arquivo = open("livros.txt", "w")
arquivo.write("Grande Sertão|1956\n")
arquivo.close()
Os 19 livros que já estavam no arquivo foram embora. Sobrou um.
o que resolve
# "a" escreve no final e preserva o resto
arquivo = open("livros.txt", "a")
arquivo.write("Grande Sertão|1956\n")
arquivo.close()

Regra prática

"a" para acrescentar um item. "w" só quando você tem a lista completa em memória e vai regravar o arquivo inteiro — que é exatamente o que faremos no método salvar() mais adiante.

ESCRITA

Escrevendo com write()

O método recebe uma string e a envia pelo fluxo. Uma string por vez, exatamente como ela é.

escrever.py
arquivo = open("livros.txt", "w", encoding="utf-8")

arquivo.write("Dom Casmurro|1899\n")
arquivo.write("Vidas Secas|1938\n")
arquivo.write("Capitães da Areia|1937\n")

arquivo.close()
print("Arquivo gravado.")

write() não pula linha

Diferente do print(), ele escreve só o que você mandou. Sem o \n no fim, tudo vira uma linha só.

sem \n: Dom Casmurro|1899Vidas Secas|1938Capitães… com \n: Dom Casmurro|1899 Vidas Secas|1938 Capitães da Areia|1937
write() só aceita string. Para gravar um número, converta antes: write(str(1899)) — senão você recebe um TypeError.

LEITURA

Três formas de ler

Todas leem o mesmo arquivo. O que muda é o formato do que você recebe de volta.

read()
texto = arquivo.read()
'Dom Casmurro|1899\n Vidas Secas|1938\n Capitães da Areia|1937\n'

Uma string só

O arquivo inteiro em uma única string. Simples, mas ocupa memória se o arquivo for grande.

readline()
linha = arquivo.readline()
'Dom Casmurro|1899\n'

Uma linha

Lê até a próxima quebra de linha. Chamar de novo devolve a linha seguinte. No fim, devolve string vazia.

readlines()
linhas = arquivo.readlines()
['Dom Casmurro|1899\n', 'Vidas Secas|1938\n', 'Capitães da Areia|1937\n']

Uma lista

Cada item é uma linha, com o \n no final. Prático para percorrer com for.

Repare: o \n vem junto em todos os casos. Antes de usar o texto, limpe com linha.strip().

O JEITO RECOMENDADO

Percorrer o arquivo linha a linha

O objeto devolvido por open() pode ser usado direto em um for. O Python entrega uma linha por vez e carrega só o pedaço necessário na memória.

ler.py
arquivo = open("livros.txt", "r", encoding="utf-8")

for linha in arquivo:
    linha = linha.strip()      # tira o \n
    if linha == "":          # ignora linha vazia
        continue
    titulo, ano = linha.split("|")
    print(f"{titulo} ({ano})")

arquivo.close()
Dom Casmurro (1899) Vidas Secas (1938) Capitães da Areia (1937)

A dupla que sempre aparece

strip() limpa espaços e quebras nas pontas. split("|") reparte a linha nos campos.

DETALHE QUE EXPLICA MUITO BUG

O arquivo tem um cursor

Enquanto o arquivo está aberto, o Python guarda em que posição você parou. Toda leitura continua de onde a anterior terminou.

A consequência

Depois de um read(), o cursor está no fim. Um segundo read() devolve string vazia — e o aluno jura que o arquivo está vazio.

Como voltar

arquivo.seek(0) leva o cursor de volta ao início. arquivo.tell() mostra a posição atual. Fechar e abrir de novo também resolve.

BOA PRÁTICA OBRIGATÓRIA

Use with e esqueça o close()

O bloco with fecha o arquivo automaticamente ao terminar — inclusive quando acontece um erro no meio do caminho.

frágil
arquivo = open("livros.txt", "r")
conteudo = arquivo.read()
numero = int(conteudo)   # se der erro aqui…
arquivo.close()          # …esta linha nunca roda
O arquivo fica aberto, segurando recursos do sistema, até o programa inteiro terminar.
correto
with open("livros.txt", "r", encoding="utf-8") as arquivo:
    for linha in arquivo:
        print(linha.strip())

# aqui fora o arquivo já está fechado

Como ler o with

"Enquanto eu estiver dentro deste bloco, o arquivo está aberto com o apelido arquivo. Ao sair — por qualquer motivo — feche."

A partir daqui, todo código desta aula usa with. É o padrão esperado em qualquer código Python profissional.

ONDE O ARQUIVO MORA

Caminho relativo e caminho absoluto

Relativo — a partir de onde o programa roda

Rodando main.py dentro de biblioteca/:

open("dados/livros.txt")

Absoluto — o endereço completo

open("C:/Users/aluno/biblioteca/dados/livros.txt")

Funciona só nesse computador. Evite em trabalhos que serão entregues.

Barra invertida em string é caractere especial. Use / mesmo no Windows, ou r"C:\pasta\arq.txt".

LIGANDO COM A AULA ANTERIOR

Quando o arquivo não colabora

Mexer com arquivo é mexer com o mundo de fora do programa: o arquivo pode não existir, estar protegido ou com conteúdo estragado. Tratar exceções deixa de ser enfeite e vira necessidade.

carregar_seguro.py
try:
    with open("livros.txt", "r", encoding="utf-8") as f:
        for linha in f:
            titulo, ano = linha.strip().split("|")
            print(titulo, int(ano))

except FileNotFoundError:
    print("Ainda não há livros cadastrados.")
except PermissionError:
    print("Sem permissão para ler o arquivo.")
except ValueError:
    print("Há uma linha fora do formato esperado.")

CONTINUANDO…

Do objeto para o arquivo

Um arquivo de texto guarda caracteres. Um objeto tem atributos, tipos e comportamento. Alguém precisa fazer a tradução entre os dois mundos — e esse alguém é você.

CONCEITO

Serializar é achatar o objeto em texto

Não dá para escrever um objeto no disco do jeito que ele é. É preciso escolher um formato de texto que represente seus atributos — e saber remontar o objeto a partir dele.

Quem decide o formato é você. Aqui vamos usar campos separados por | — o mesmo princípio de um arquivo CSV, só que com outro separador.

DECISÃO DE PROJETO

Escolhendo o formato da linha

  • Um objeto por linha. Fica fácil percorrer com for e o arquivo continua legível por humanos.
  • Ordem fixa dos campos. Título, autor, ano — sempre nessa ordem, para os dois lados saberem o que esperar.
  • Um separador que não apareça nos dados. Vírgula é arriscada em títulos; | quase nunca aparece.
  • Tudo vira texto na ida. Na volta, converta de novo: int(ano).
Dom Casmurro|Machado de Assis|1899 ↑ ↑ ↑ título autor ano

O contrato invisível

Se para_linha() gravar em uma ordem e de_linha() ler em outra, o programa não acusa erro — só passa a mostrar o autor no lugar do título.

Na parte 2 da aula veremos o JSON, que resolve isso com nomes de campos e dispensa esse acordo silencioso.

EXEMPLO COMPLETO · 1 DE 4

A classe que sabe se descrever

Cada objeto conhece o próprio formato de gravação. A classe Livro não abre arquivo nenhum — ela só traduz.

livro.py
class Livro:

    def __init__(self, titulo, autor, ano):
        self.titulo = titulo
        self.autor = autor
        self.ano = ano

    def para_linha(self):
        """Objeto -> uma linha de texto."""
        return f"{self.titulo}|{self.autor}|{self.ano}\n"

    @staticmethod
    def de_linha(linha):
        """Uma linha de texto -> objeto."""
        titulo, autor, ano = linha.strip().split("|")
        return Livro(titulo, autor, int(ano))

    def __str__(self):
        return f"{self.titulo} — {self.autor} ({self.ano})"

Duas operações espelhadas

para_linha() monta a string. de_linha() desmonta. Uma é o inverso exato da outra.

Por que @staticmethod

Quando chamamos de_linha() ainda não existe objeto — ele é justamente o resultado. Então o método pertence à classe, não a uma instância: Livro.de_linha(linha).

Isto é encapsulamento em ação: quem usa a classe não precisa saber que o separador é |.

EXEMPLO COMPLETO · 2 DE 4

A classe que cuida do arquivo — salvar

A Biblioteca guarda a lista em memória e sabe gravá-la inteira no disco.

biblioteca.py
from livro import Livro

class Biblioteca:

    def __init__(self, arquivo="livros.txt"):
        self.arquivo = arquivo
        self.livros = []

    def adicionar(self, livro):
        self.livros.append(livro)

    def salvar(self):
        with open(self.arquivo, "w", encoding="utf-8") as f:
            for livro in self.livros:
                f.write(livro.para_linha())

Por que "w" aqui é seguro

A lista em memória é a versão completa e mais atual. Regravar o arquivo inteiro mantém os dois em sincronia, inclusive quando um livro foi removido.

Divisão de responsabilidades

Livro sabe virar texto. Biblioteca sabe conversar com o arquivo. Nenhuma das duas faz o trabalho da outra.

Trocar o formato depois — para CSV ou JSON — vai mexer em duas ou três linhas, não no programa inteiro.

EXEMPLO COMPLETO · 3 DE 4

A classe que cuida do arquivo — carregar

O caminho de volta: ler cada linha, reconstruir o objeto, encher a lista.

biblioteca.py · continuação
    def carregar(self):
        self.livros = []
        try:
            with open(self.arquivo, "r", encoding="utf-8") as f:
                for linha in f:
                    if linha.strip() == "":
                        continue
                    self.livros.append(Livro.de_linha(linha))

        except FileNotFoundError:
            # primeira execução: ainda não há arquivo
            pass
        except ValueError:
            print("Aviso: há linha fora do formato; ignorando.")

    def listar(self):
        for i, livro in enumerate(self.livros, start=1):
            print(f"{i}. {livro}")

Limpar antes de encher

self.livros = [] na primeira linha evita duplicar tudo se carregar() for chamado duas vezes.

Linha em branco no fim

Quase todo arquivo termina com \n, o que produz uma última linha vazia. O continue resolve.

Note o pass no except: aqui ele é intencional e comentado. Um except mudo e sem explicação é o que esconde bug.

RESUMO

O que fica desta aula

Conceitos

Dados na memória são voláteis. Persistir é gravar em disco. O canal entre programa e arquivo é o fluxo, e ele tem duas direções.

Ferramentas

open() com caminho, modo e encoding. write() para gravar, for no arquivo para ler. with para fechar sozinho.

Modos

"r" lê, "a" acrescenta, "w" apaga e regrava. Escolher errado é a causa mais comum de dado perdido.

Objetos

Serializar é traduzir o objeto em uma linha de texto; desserializar é o caminho de volta. para_linha() e de_linha().

Projeto

A classe do objeto sabe se traduzir; a classe da coleção sabe falar com o arquivo. Responsabilidades separadas.

Robustez

Arquivo é o mundo de fora: pode não existir, estar protegido ou vir estragado. Trate as exceções sempre.

PARA CONHECER

Outros formatos para persistência de objetos

O formato com | funciona, mas quebra quando o objeto tem lista dentro, ou quando o título contém o separador. Existem formatos prontos para isso.

  • CSV com o módulo csv — o formato de planilha, com o tratamento de vírgulas já resolvido
  • JSON com o módulo json — campos com nome, listas e objetos aninhados
  • pickle — grava o objeto Python inteiro, em binário, sem escrever tradução à mão
Mais adiante, a pergunta seguinte é quando o arquivo deixa de dar conta — e aí entram os bancos de dados.
